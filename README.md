# 和平精英 · 红点基准四域 × 八状态统一模型

> 目标：以 **红点 / 全息 / 机瞄** 为绝对基准，把 **开镜、开镜开火、陀螺仪、陀螺仪开火** 四个域统一到同一套初等数学模型。
>
> 每个域都包含 **第三人称不开镜、第一人称不开镜、红点/全息/机瞄、2 倍、3 倍、4 倍、6 倍、8 倍** 八种状态，共 **4 × 8 = 32** 个灵敏度槽。
>
> 实测素材：`80/`、`90/` 两组 2400×1080、20:9 截图；10m 靶；TPP/倍镜每组 7 张（第三人称 + 红点 + 2X/3X/4X/6X/8X），另有 FPP 80/90/103 三张（`80/80.jpg`、`90/90.jpg`、`103.jpg`）。实测日期：2026-10-26（TPP/倍镜）、2026-10-27（FPP）；灵敏度反推：2026-10-28（`lite/` 四域统一控制截图）。
>
> **单位约定：** 游戏内 TPP / FPP 视野滑块用 **%**（80/90/103%）；本模型的几何量用水平 FOV 角度 **°**。当前版本按 80% ↔ 80°、90% ↔ 90°、103% ↔ 103° 对应。
>
> **两个 FOV 必须分开：**
> - **视觉 FOV**（画面）：80% / 90% / 103%，只决定你看到多宽；
> - **灵敏度 FOV**（TPP/FPP 的有效值）：由游戏统一控制反推约 **75–77°**，默认 **75°**，决定同样手势转多快。
>
> 下文 `F` 是角度；TPP/FPP 的 `k` 用 `F_sens`，倍镜的 `k` 用实测水平 FOV。

## 1. 一句话结论

八种状态共用一组 **屏幕角增益系数**：

| 状态 | 默认 FOV（°） | 相对红点放大率 `m` | 灵敏度系数 `k = 1/m`（无量纲） | 归一化灵敏度（红点 = 100%） |
|---|---:|---:|---:|---:|
| 第三人称不开镜（TPP） | 75.0°（灵敏度 FOV；画面 80%） | 0.6813 | **1.4678** | **146.8%** |
| 第一人称不开镜（FPP） | 75.0°（灵敏度 FOV；画面 90%） | 0.6813 | **1.4678** | **146.8%** |
| 红点 / 全息 / 机瞄 | 55.2° | 1.0000 | 1.0000 | 100.0% |
| 2 倍 | 44.3° | 1.2828 | 0.7796 | 78.0% |
| 3 倍 | 26.7° | 2.2049 | 0.4535 | 45.4% |
| 4 倍 | 20.0° | 2.9642 | 0.3374 | 33.7% |
| 6 倍 | 13.3° | 4.4698 | 0.2237 | 22.4% |
| 8 倍 | 11.0° | 5.4103 | 0.1848 | 18.5% |

四个域都用同一组 `k`，各自只改 **红点基准值**，并按各自上限截断：

```text
S(域, 状态) = clamp( round( B(域, 红点) × k(状态) ), 0, cap(域) )   [单位：%]
倍镜：k(状态) = tan(FOV状态 / 2) / tan(FOV红点 / 2) = 1 / m(状态)
TPP/FPP：k = tan(F_sens / 2) / tan(FOV红点 / 2)，F_sens 默认 75°
cap(开镜 / 开镜开火) = 300（即 300%）
cap(陀螺仪 / 陀螺仪开火) = 600（即 600%）
```

其中 `B` 是你在该域给红点/全息/机瞄设置的值，单位是 **%**（例如 100 表示 100%）。**上限不同不改变 `k`**：陀螺仪能填到 600%，不代表它的系数要翻倍。

- **跨八状态**：同一手势（以及默认“屏幕等距”口径下的同一陀螺仪转角），准星在屏幕上的位移比例一致；
- **跨四域**：四条曲线形状完全一致，只需分别校准红点基点；
- **不开镜**：TPP/FPP 的 `k ≈ 1.47`，因为有效灵敏度视野比红点更宽；但它不等于视觉 FOV 的比例，`m` 也不再是画面放大率；
- **开火域**：后坐力是额外叠加项，不能靠灵敏度“抵消”，只能整体乘一个常数，不能逐状态乱改；
- **上限**：镜头域 0–300%，陀螺仪域 0–600%。因为 TPP/FPP 的 `k > 1`，高红点基准下它们会先触顶；`clamp` 只截断结果，不改变 `k`。

## 2. 实测 FOV

### 2.1 测量方法

同一张 10m 靶纸、同一站位，截图后取靶心 **红色区域外接框** 的宽×高（像素）。用几何平均消掉轻微的椭圆/透视误差：

```text
m_s = sqrt( (w_s / w_红点) × (h_s / h_红点) )
```

`m_s` 是倍镜相对红点的实际放大率，不依赖靶纸真实尺寸、不依赖距离，因此比“按标称倍率算”可靠。

### 2.2 原始像素与放大率

| 状态 | 游戏视野 80% 红靶像素（宽×高） | 游戏视野 90% 红靶像素（宽×高） | 相对红点 `m` |
|---|---:|---:|---:|
| 第三人称不开镜 | 40.0 × 56.0 | 33.0 × 47.0 | —（含相机后移，不能直接比） |
| 红点/全息/机瞄 | 80.0 × 111.5 | 80.0 × 112.0 | 1.0000 |
| 2 倍 | 103.0 × 142.5 | 103.0 × 143.0 | 1.2828 |
| 3 倍 | 177.0 × 245.0 | 177.0 × 245.0 | 2.2049 |
| 4 倍 | 237.5 × 330.0 | 237.0 × 330.0 | 2.9642 |
| 6 倍 | 357.5 × 498.5 | 357.0 × 498.0 | 4.4698 |
| 8 倍 | 433.0 × 603.0 | 433.0 × 603.0 | 5.4103 |

两组同一倍镜按宽高几何平均折算的 `m` 差 **< 0.3%**，在截图分辨率下属于 JPEG/抗锯齿误差。作为对照，同一张“不开镜”参考图里红靶从 **40×56（游戏视野 80%）** 缩到 **33×47（游戏视野 90%）**，说明 90% 的基础视野确实更宽；但所有倍镜像素不变，说明倍镜 FOV 是固定的。

### 2.4 不开镜的有效灵敏度 FOV（反推）

`lite/` 里的四张图是游戏“按开镜倍率统一控制灵敏度”主滑块 = 100 时的状态：下方八类由游戏自动生成，不是手动逐项设置。实测结果为：

| 域 | 红点 | TPP / FPP | 反推 `F_sens`（线性 tan） | 反推 `F_sens`（官方 0.93 曲线） |
|---|---:|---:|---:|---:|
| 开镜 / 陀螺仪 | 69% | 100% | 74.3° | 75.8° |
| 开火两域 | 68% | 100% | 75.1° | 76.7° |

反推公式：

```text
F_sens = 2 · atan( (S_游戏 / S_红点) · tan(55.2°/2) )
```

两条曲线都收敛到 **75–77°**，说明 TPP/FPP 的灵敏度基准不是画面上的 80/90/103°。取 `F_sens = 75°`：

| 输入 | 数值 |
|---|---:|
| `F_sens` | 75.0° |
| `m = tan(55.2°/2) / tan(75°/2)` | 0.6813 |
| `k = 1/m` | **1.4678（146.78%）** |
| 红点 68% → TPP/FPP | **100%**（99.81 取整） |
| 红点 69% → TPP/FPP | **101%**（101.28 取整） |
| 红点 100% → TPP/FPP | **147%** |

> 默认参数：视觉 FOV 仍是 TPP 80% / FPP 90%，`F_sens` 默认 75°。因此默认输出里 TPP/FPP 的 `k` 都是 **146.78%**，镜头 147 / 陀螺仪 440。
>
> 这里的 `k` 是“相对红点”的比例，不是游戏内该槽位的独立校准值。游戏里 TPP、FPP 各有自己的灵敏度槽；本模型给出的是让它们与红点保持同一屏幕位移比例的建议值。
>
> 换视觉 FOV 后，`F_sens` 不会自动跟着变；请用计算器/Excel 的“从游戏值反推”重新标定。

### 2.6 为什么不用“不开镜”截图直接反推红点 FOV

这里说的“不开镜”指旧的第三人称参考图：相机在角色后方；ADS 相机在角色眼睛位置。腰射红靶约 40×56，红点约 80×111.5，像素比约 **2.00×**，但其中混入了相机后移的距离放大。

按 `F₀ = 55.2°`、游戏视野 80%（水平 FOV 80°）计算，红点相对腰射的光学放大是：

```text
tan(80/2) / tan(55.2/2) = 0.8391 / 0.5228 = 1.605×
```

剩余的比例：

```text
2.00 / 1.605 = 1.246×
```

约对应第三人称相机后移 25%（10m 靶 → 相机约 12.5m）。所以红点锚点不能拿腰射像素直接除 2，必须用 ADS 倍镜链（3/4/6 倍）校准；这也反过来验证了 `55.2°` 与第三人称相机偏移是自洽的。

> 相机后移影响的是目标在画面里的像素大小（透视/视差），不改变镜头的角 FOV。视觉 FOV 的几何计算用 80/90，所以能用 1.605× 解释像素比；但**灵敏度 FOV 是另一个量**，由游戏统一控制反推约 75°，不能拿 80/90 直接算 TPP/FPP 的 `k`。
>
> FPP 相机在眼睛位置，没有第三人称的后移项；它的视觉 FOV 仍按 80/90/103 校验（见 2.5），灵敏度同样用 `F_sens ≈ 75°`。

## 3. 数学模型

### 3.1 针孔投影

设：

- `F_s`：状态 `s` 的水平 FOV；
- `W`：屏幕宽度（像素）；
- `θ`：目标偏离屏幕中心的角度；
- `x`：目标在屏幕上的横向像素位置。

20:9 屏幕的水平针孔投影为：

```text
x = (W/2) · tan(θ) / tan(F_s/2)
```

对 `θ` 求导（也可直接写成小角度差分 `Δx/Δθ`），得到 **屏幕像素对角度的局部增益**：

```text
dx/dθ = W / ( 2 · tan(F_s/2) )
```

### 3.2 为什么灵敏度要乘 `tan(F/2)`

设灵敏度值 `S` 与“输入 → 镜头角速度”近似成正比：

```text
dθ/du = c · S
```

`u` 是手指滑动距离或陀螺仪转角。则屏幕上的移动速度：

```text
dx/du = (dx/dθ) · (dθ/du)
      = W · c · S / ( 2 · tan(F_s/2) )
```

要让不同状态在**同一输入**下得到**同一屏幕位移比例**，必须令：

```text
S_s / tan(F_s/2) = 常数
```

即：

```text
S_s = S₀ · tan(F_s/2) / tan(F₀/2)
    = S₀ / m_s
```

其中 `S_s`、`S₀` 的单位均为 **%**。这就是本模型的“**tan 律 / 屏幕等距律**”。它比简单的 `S ∝ F` 更准，尤其是 8 倍这种小 FOV 倍镜。

### 3.3 四域 × 八状态统一公式

设四个域的红点基准分别为：

- `B_ads`：开镜
- `B_adsf`：开镜开火
- `B_gyro`：陀螺仪
- `B_gyrof`：陀螺仪开火

状态集合：

```text
s ∈ { TPP, FPP, 1X, 2X, 3X, 4X, 6X, 8X }
```

则任意状态 `s`：

```text
S_ads,s   = min(300, round( B_ads   × k_s ))   # 单位：%
S_adsf,s  = min(300, round( B_adsf  × k_s ))   # 单位：%
S_gyro,s  = min(600, round( B_gyro  × k_s ))   # 单位：%
S_gyrof,s = min(600, round( B_gyrof × k_s ))   # 单位：%

倍镜：k_s = tan(F_s/2) / tan(F_红点/2) = 1 / m_s
TPP/FPP：k = tan(F_sens/2) / tan(F_红点/2)，F_sens 默认 75°
```

四个域共用 `k_s`，这就是“统一”的核心。镜头域（开镜、开镜开火）上限 300%，陀螺仪域（陀螺仪、陀螺仪开火）上限 600%；上限只截断结果，不改变 `k_s`。

> `k_s` 的取值范围不再局限于 `0 < k ≤ 1`：倍镜段是 `0.1848–1.0000`，TPP/FPP 是 **1.4678**（`F_sens = 75°`）。`k > 1` 不是错误，而是“有效灵敏度视野比红点更宽”的直接结果；它不再随视觉 FOV 80/90/103 变化。

|---|---:|---:|---:|---:|
| 第三人称不开镜 | 300（MAX） | 300（MAX） | 600（MAX） | 600（MAX） |
| 第一人称不开镜 | 300（MAX） | 300（MAX） | 600（MAX） | 600（MAX） |
| 红点/全息/机瞄 | 300 | 300 | 600 | 600 |
| 2 倍 | 234 | 234 | 468 | 468 |
| 3 倍 | 136 | 136 | 272 | 272 |
| 4 倍 | 101 | 101 | 202 | 202 |
| 6 倍 | 67 | 67 | 134 | 134 |
| 8 倍 | 55 | 55 | 111 | 111 |

> 这张表故意展示上限的效果：TPP/FPP 的 `k > 1`，当红点已经取到 300%/600% 时，不开镜结果必然被截断。想保留 TPP/FPP 的比例，镜头红点应不超过约 **204%**，陀螺仪红点应不超过约 **409%**（按 `k = 1.4678`）。

### 4.3 开火域要不要更高？

后坐力是 **加性扰动**，不是乘性增益。灵敏度只能统一“你拖动/转手机 → 镜头转多少”，不能统一“枪口自己跳多少”。

正确做法：

```text
B_adsf  = c_fire × B_ads
B_gyrof = c_gyrofire × B_gyro
```

`c_fire`、`c_gyrofire` 是**四域之间的整体常数**，所有八种状态共用；不要给 3 倍单独加 5%、给 6 倍单独减 3%。否则跨状态曲线又被破坏。

上限会限制 `c` 的可用范围：镜头域乘完不能超过 300%，陀螺仪域不能超过 600%；触顶时不要靠改单个状态的 `k` 来绕过。

若追求“四域完全同感”，先取 `c_fire = c_gyrofire = 1`，只在整体压不住后坐力时再统一调大。

## 5. 怎么用

### 5.1 直接套公式

1. 先确认 TPP、FPP 的**灵敏度 FOV**：默认 `F_sens = 75°`；若你有游戏统一控制的实际值，用第 2.4 节公式反推后填入。视觉视野 80%/90%/103% 只用于画面，不参与这一步。
2. 打开游戏灵敏度设置，记下你四个域的红点值（单位 %）：`B_ads / B_adsf / B_gyro / B_gyrof`。
3. 对每个状态，用 `k_s` 相乘，四舍五入到整数；镜头域（开镜/开镜开火）范围 **0–300%**，陀螺仪域（陀螺仪/陀螺仪开火）范围 **0–600%**。
4. 开火域与对应非开火域用同一组 `k_s`，只改 `B`；若乘法结果超过本域上限，按上限截断。

### 5.2 用计算器

- `calculator.html`：浏览器直接打开，输入视觉 FOV、灵敏度 FOV、四个红点基准（%），自动输出四域 × 八状态共 32 个值（%）。左上角“从游戏值反推”可填 TPP / FPP / 红点，自动算出并写入灵敏度 FOV。
- `fov_model.xlsx`：Excel 计算器，黄色单元格是输入（% 或 °），其余自动算；`B13` 是灵敏度 FOV，`A34` 起有反推区；同样覆盖 8 种状态，`FOV实测` 页保留几何校验。
- `server.ts`：Bun 静态服务器；运行 `bun server.ts` 后访问 `http://localhost:8080/`，默认直接打开计算器（`PORT=3000 bun server.ts` 可换端口）。

### 5.3 标定红点基准

模型只决定“状态之间的比例”，不决定“红点本身多少”。红点基准建议用下面的方法定一次：

**开镜/开火（手指）**

1. 红点，10m 靶，准星放在靶心；
2. 手指从屏幕中心横向划到屏幕边缘（约半屏）；
3. 记录镜头转过的角度（看罗盘/地标）；
4. 调 `B_ads`（%），使“半屏滑动 ≈ 你习惯的角度”，例如 90°；
5. `B_adsf` 先与 `B_ads` 相同，压不住后坐力再整体乘 `c_fire`。

**陀螺仪/陀螺仪开火**

1. 红点，准星放在靶心；
2. 手机水平旋转 90°；
3. 看镜头是否也转 90°（1:1），或你习惯的比例；
4. 调 `B_gyro` 到目标比例（上限 600%）；
5. `B_gyrof` 先与 `B_gyro` 相同，再按后坐力整体乘 `c_gyrofire`（上限 600%）。

**验证**

- 同一根手指、同样的滑动距离，在 TPP、FPP、2/3/4/6/8 倍下，准星应移动**相同的屏幕比例**（不是相同的角度）；
- 陀螺仪转同样的角度，若采用“屏幕等距”模型，准星也应移动相同的屏幕比例；
- TPP/FPP 数值高于红点是正常的；如果它们触顶，先降低该域红点基准，或接受上限截断；
- 如果某个状态偏快/偏慢，先检查 `F_s` / `m_s` 是否填错，不要直接改该状态的数值。

## 6. 版本联动与非线性修正

### 6.1 若倍镜 FOV 随基础视野联动

你的截图显示当前版本 **不联动**。如果某版本变成联动，保持“相对放大率 `m_s` 不变”，则：

```text
F_s(新视野) = 2 · atan( tan(F_新视野/2) / M_s )
```

其中 `M_s` 是该倍镜相对“不开镜”的放大率。也可以直接用比例：

```text
tan(F_s(90)/2) = tan(F_s(80)/2) · tan(90/2) / tan(80/2)
```

本模型下 80 → 90 的参考值（仅当版本联动时使用）：

| 状态 | FOV @ 80 | FOV @ 90（联动假设） |
|---|---:|---:|
| 红点/全息/机瞄 | 55.2° | 63.8° |
| 2 倍 | 44.3° | 51.8° |
| 3 倍 | 26.7° | 31.6° |
| 4 倍 | 20.0° | 23.7° |
| 6 倍 | 13.3° | 15.9° |
| 8 倍 | 11.0° | 13.1° |

如果倍镜联动但红点不联动，则只换倍镜 FOV，重新算 `k_s`；如果两者都联动，`k_s` 基本不变（因为红点也一起变宽）。

### 6.2 不开镜：视觉 FOV 与灵敏度 FOV 分开

TPP/FPP 的 `k` 不再直接跟随视觉 FOV，而是跟随反推得到的有效灵敏度 FOV：

```text
k_tpp = k_fpp = tan(F_sens/2) / tan(55.2°/2)
```

- `F_sens = 75°` → `k = 1.4678`；
- 游戏统一控制红点 68 / TPP 100 → `F_sens ≈ 75.1°`；
- 红点 69 / TPP 100 → `F_sens ≈ 74.3°`。

视觉 FOV 从 90% 改到 103% 时，画面变宽，但 `k` 仍是 1.4678；如果新视野下游戏自动值不再对齐，重新做一次反推。计算器把视觉 FOV 和灵敏度 FOV 做成两个独立输入，就是为了避免把两者混为一谈。

### 6.3 若游戏灵敏度不是线性映射

上面的推导假设 `dθ/du ∝ S`。若游戏实际是曲线 `g(S)`，则：

```text
g(S_s) = g(B) × k_s
S_s = g⁻¹( g(B) × k_s )
```

若用幂律近似：

```text
g(S) = a · S^p
S_s = B × k_s^(1/p)
```

标定 `p`：

1. 红点，设 `S1`，固定滑动距离，记录转角 `α1`；
2. 设 `S2`，同样滑动，记录 `α2`；
3. `p = ln(α2/α1) / ln(S2/S1)`。

`p = 1` 就是本模型默认的线性情况。大多数版本接近线性，可直接用 `S = B × k`。

## 7. 陀螺仪的两种“统一”口径

这是最容易争议的一点，必须明确你选哪一种：

### A. 屏幕等距（本模型默认，推荐给“视觉手感统一”）

```text
k_s = 1/m_s
```

同样的手机转角，在不同状态下准星移动**相同的屏幕比例**。高倍镜数值会明显更低（8 倍只有红点的 18.5%），而不开镜会高于红点（TPP/FPP 为 146.8%）。

优点：任何状态下都不会“一碰就飞”，跟枪视觉速度一致。
缺点：手机转 90°，8 倍镜头并不会转 90°，而是更少；不是物理 1:1。

### B. 角度 1:1（推荐给“陀螺仪物理直觉”）

```text
k_s = 1（所有八种状态相同）
```

手机转 90°，镜头也转 90°；高倍镜下目标在屏幕上移动更大，这是正常的望远镜物理效果。

优点：陀螺仪像“转头”，物理直觉最好。
缺点：高倍镜屏幕灵敏度高，需要更细的手腕控制。

**不要混用**：要么四域全部用 A，要么陀螺仪两域用 B、开镜两域用 A；不要 2 倍用 A、6 倍用 B。选定后，跨状态才真正统一。

## 8. 适用范围与误差

- FOV 是 **水平 FOV**；若游戏内部用垂直 FOV，需按 `tan(F_h/2) = 宽高比 × tan(F_v/2)` 转换，灵敏度模型仍用水平 FOV，因为屏幕宽度是横向的。
- 本模型是屏幕中心的一阶线性化：`dx/dθ = W/(2·tan(F/2))`。离中心越远，tan 非线性越明显；高倍镜边缘的“视觉加速”会略强于中心，这是投影本身的性质，不是系数算错。
- 测量误差主要来自红靶边缘抗锯齿、JPEG 压缩、截图时轻微透视。按像素外接框估计，`m_s` 误差约 ±1%，FOV 误差约 ±0.3°～±0.8°。
- 红点锚点 `55.2°` 是由 3/4/6 倍与标称 `80/M` 视场互相校验得到；若你只信 10m 靶纸绝对尺寸，红点可能在 52°–57° 区间。锚点变化时，所有 FOV 按比例微调，但倍镜 `k_s` 完全不变（因为 `k_s = 1/m_s` 只依赖相对放大率）。**TPP/FPP 例外**：它们的 `k = tan(F/2)/tan(F红点/2)` 是绝对视野比，红点锚点变化时 `k` 会跟着变；本工具固定用 `F红点 = 55.2°`。
- **TPP/FPP 是唯一 `k > 1` 的两行**：不开镜视野比红点宽，要保持同样的屏幕位移比例，数值必然更高。`m < 1` 不是“灵敏度低”，而是“放大率小于 1”。
- **不要用腰射靶像素直接算 TPP 的 `k`**：40×56 对 80×111.5 的 2.00× 含第三人称相机后移；扣除后光学比例约 1.605×，对应视觉 FOV 80°。这个数只验证画面几何，不进入 TPP/FPP 灵敏度；后者用 `F_sens ≈ 75°`（反推见 2.4）。
- **上限会先截断开镜段**：镜头域 300% 时，红点基准超过约 **204%** 就会先截断 TPP/FPP；陀螺仪域 600% 时超过约 **409%**。这是游戏槽位上限的限制，不是模型算错。
- 红点、全息、机瞄在游戏里共用同一个灵敏度槽，本模型按同一基准处理；若你实测三者成像有明显差异，把 `80/`、`90/` 中对应截图替换掉，重跑 `measure.py` 即可。
- 不同手机、不同画质、不同版本可能改 FOV 或灵敏度曲线；换版本后建议用 10m 靶复测一次 `m_s`。
- 后坐力、镜头抖动、陀螺仪噪声不属于本模型能“算掉”的部分。
